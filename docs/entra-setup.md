# Microsoft Entra ID setup

This page covers the Microsoft Entra side required by `om-auth entra` (the installed wrapper around `configure-entra.sh`).

## 1. Create an app registration

In the Microsoft Entra admin center, create an application registration for OpenMetadata.

For a typical single-tenant deployment, choose:

**Accounts in this organizational directory only**

Record:

- Directory (tenant) ID
- Application (client) ID

The toolkit asks for both values interactively when you run `om-auth entra`.

## 2. Add the OpenMetadata redirect URI

Add a **Web** platform redirect URI:

```text
https://YOUR-OPENMETADATA-HOST/callback
```

Example:

```text
https://metadata.example.com/callback
```

The public URL supplied to the script must match the externally visible HTTPS URL used by your users.

## 3. Create a client secret

Under **Certificates & secrets**, create a client secret.

Copy the secret **Value** immediately and store it securely.

The script needs the client secret **value**, not the Secret ID.

The value is entered using a hidden terminal prompt.

## 4. OIDC settings generated by the toolkit

The toolkit configures OpenMetadata with:

```text
provider: azure
client type: confidential
response type: code
scope: openid email profile offline_access
client authentication method: client_secret_post
preferred JWS algorithm: RS256
```

It derives these URLs from the tenant ID:

```text
Authority:
https://login.microsoftonline.com/TENANT_ID

Discovery:
https://login.microsoftonline.com/TENANT_ID/v2.0/.well-known/openid-configuration

Microsoft JWKS:
https://login.microsoftonline.com/TENANT_ID/discovery/v2.0/keys
```

It derives the OpenMetadata callback URL as:

```text
PUBLIC_OPENMETADATA_URL/callback
```

## 5. Why offline_access is included

OpenMetadata may need a refresh token after the initial authorization-code exchange. Microsoft only returns a refresh token when `offline_access` is requested, so the toolkit includes it in the scope.

## 6. Test in a private browser session

After `om-auth entra` reports success, open the public OpenMetadata URL in an incognito/private browser window and verify that the Microsoft sign-in flow completes.

Do not remove the rollback backup until you have tested a fresh sign-in.

## Troubleshooting

### AADSTS7000215 / invalid client secret

Make sure you entered the **client secret value**, not the Secret ID.

### Redirect URI mismatch

Confirm that the Entra Web redirect URI exactly matches:

```text
PUBLIC_OPENMETADATA_URL/callback
```

Check scheme, hostname, port (if any), path, and trailing slashes.

### No refresh token

Confirm the generated OpenMetadata scope contains:

```text
openid email profile offline_access
```

### OpenMetadata does not recover after the change

Restore the pre-change backup:

```bash
om-auth restore ~/.local/share/openmetadata-auth-toolkit/backups/security-config-YYYYMMDD-HHMMSS.yaml
```
